## How the prices were set

Against your own catalogue first. Comparable reads on the exchange cost 0.01–0.10 USDC —
`risk.score` 0.02, `transaction.simulate` 0.02, `token.intelligence` 0.03, `launch.check`
0.03, `transaction.explain` 0.05, `contract.inspect` 0.08, `research.asset` 0.10. Each
listing sits at or just below its nearest comparable, so a buyer choosing between them is
choosing on the answer, not the price.

Then by what a call costs to serve, counted in round trips: one account read for
`mint_audit`, three for `inspect_exit`, a single finalized transaction for
`prove_payment`, up to eight by default (sixteen at most) for one `mesh` run.

Then by the rail. Settlement is USDC, so a buyer's price does not move between quote and
payment, and no price is below 0.02 so the buyer's Solana network fee stays a small part
of what they pay. `inspect_payment` is priced low on purpose: it protects payments worth
far more than it costs, but only for a buyer who runs it before every one.

Prices are gross; any exchange share is yours to state.

## Inputs and outputs

Every input schema is generated from the same tool definition the MCP server registers,
so a request valid for the listing is valid for the tool. Output schemas list the fields
a buyer can rely on — each tool returns more — and each was checked against a real output
recorded from that tool on 23 September.

Three things in the outputs matter to how you record receipts:

- **Verdicts are about evidence.** `inspect_payment`, `prove_payment` and `mesh` each
  distinguish "the chain could not settle this" (`unproven`) from a negative answer. A
  receipt or UI that collapses the two would misreport the result.
- **Every list says how complete it is**, in `completeness`: `exhaustive`, `curated`,
  `truncated` or `failed`.
- **Text written on-chain is marked**, e.g. a transaction memo arrives as
  `{ text, untrusted: true, source }`.
